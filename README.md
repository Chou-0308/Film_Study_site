# 1단계 · 외부 그림 내려받기

## 왜 해야 하나요

지금 사이트의 그림 중 **79장은 우리 폴더에 없습니다.** imgur, StudioBinder 같은
**남의 서버 주소를 그때그때 불러오는 방식**입니다.

| 어디서 오는가 | 몇 장 |
|---|---:|
| i.imgur.com | 49 |
| s.studiobinder.com | 10 |
| images.unsplash.com | 8 |
| film-grab.com | 6 |
| upload.wikimedia.org | 4 |
| 기타 | 2 |

이대로 두면 이런 일이 생깁니다.

- **원본이 지워지면** 학생 화면에서 그림이 사라집니다. imgur는 오래된 이미지를 종종 정리합니다.
- **학교 네트워크가 막으면** 그 그림만 안 뜹니다. imgur는 국내에서 간헐적으로 차단됩니다.
- 남의 서버가 느리면 그만큼 느리게 뜹니다.

`fetch-images.sh` 가 79장을 전부 내려받아 `img-ext/` 폴더에 넣고,
`index.html` 안의 주소도 우리 폴더 경로로 바꿔줍니다. 그러면 그림이 사이트의 일부가 됩니다.

> **유튜브 썸네일 68장은 건드리지 않습니다.** 유튜브 서버는 안 죽으니 그대로 두는 게 맞습니다.

## 어떻게 하나요

**반드시 집이나 개인 네트워크에서 하세요.** 학교망에서는 절반쯤 실패합니다.

**① 터미널 열기** — `⌘ + 스페이스` → `터미널` 입력 → 엔터

**② 이 폴더로 이동** — 터미널에 `cd ` 를 치고 (**cd 뒤에 한 칸 띄우고**),
Finder에서 이 `filmitda-study-site` 폴더를 터미널 창으로 **끌어다 놓으면** 경로가 자동으로 채워집니다.
그리고 엔터.

```
cd /Users/chogeonhwi/Desktop/학습자료/영상\ 제작\ 심화/filmitda-study-site
```

**③ 실행**

```bash
bash fetch-images.sh
```

```
  index.html 안 주소 118곳을 내 폴더 경로로 교체했습니다.
```

2~3분 걸립니다.

## 실패가 나와도 괜찮습니다

몇 장 실패하는 건 정상입니다. **못 받은 그림은 원래 주소를 그대로 두기 때문에
사이트는 그대로 돌아갑니다.** 그 주소마저 막히면 빈칸 대신 그림 설명 문구가 뜨도록 해뒀습니다.

실패한 그림이 뭐였는지는 `fetch-failed.txt` 에 남습니다.

```
- ELS 예시 — Mad Max: Fury Road
    https://s.studiobinder.com/wp-content/uploads/.../Mad-Max.jpg
```

몇 장 안 되면 그냥 두셔도 되고, 살리고 싶으면 —

1. **한 번 더 실행** — `bash fetch-images.sh` 를 그냥 다시 치면 됩니다.
   **이미 받은 건 건너뛰고 실패한 것만 다시 시도**합니다. 여러 번 돌려도 안전합니다.
2. **VPN을 켜고 실행** — imgur 차단이 원인인 경우가 많습니다.
3. **직접 저장** — `fetch-failed.txt` 의 주소를 브라우저에 붙여넣어 이미지를 저장한 뒤
   `img-ext/` 에 넣고, `index.html` 에서 그 주소만 파일명으로 바꿉니다.

## 되돌리고 싶으면

실행할 때마다 `index_bak_날짜시각.html` 로 자동 백업됩니다.
그 파일 이름을 `index.html` 로 바꾸면 실행 전으로 돌아갑니다.

# 2단계 · 배포 주소 채우기

카카오톡으로 링크를 보낼 때 **미리보기 이미지와 제목이 뜨게** 하는 설정입니다.
지금은 `GITHUB_USER/REPO_NAME` 자리표시자가 들어 있어서, 그대로 두면 미리보기가 깨집니다.

저장소 이름을 먼저 정하세요. 예를 들어 `filmitda-study` 로 정했고
GitHub 아이디가 `chogeonhwi` 라면 주소는 `https://chogeonhwi.github.io/filmitda-study/` 가 됩니다.

터미널에서 (1단계와 같은 위치):

```bash
bash set-url.sh https://chogeonhwi.github.io/filmitda-study/
```

`✓ 3곳을 ... 로 바꿨습니다.` 가 뜨면 됩니다. (og:url · og:image · twitter:image 세 군데)

# 3단계 · GitHub에 올리기

## 방법 A · 웹에서 끌어다 놓기 (터미널 필요 없음, 추천)

1. [github.com](https://github.com) 로그인 → 오른쪽 위 **+** → **New repository**
2. **Repository name** 에 2단계에서 정한 이름 (`filmitda-study`) 입력
3. **Public** 선택
   > Private으로 하면 GitHub Pages가 유료 요금제에서만 됩니다.
   > 이 사이트는 `noindex` + `robots.txt` 로 검색에 안 걸리게 해뒀으니
   > Public이어도 링크를 아는 사람만 들어옵니다.
4. **Create repository**
5. 다음 화면에서 **uploading an existing file** 클릭
6. Finder에서 이 폴더를 열고 **안에 있는 파일과 폴더를 전부 선택**해서
   (`⌘A`) 브라우저 창에 끌어다 놓습니다.
   > ⚠️ **폴더 자체가 아니라 폴더 "안의 내용물"** 을 올려야 합니다.
   > `filmitda-study-site` 폴더째로 올리면 주소가 한 단계 더 들어가서 안 열립니다.
7. 아래 **Commit changes** 클릭. 파일이 많아서 1~2분 걸립니다.

## 방법 B · 터미널

```bash
git init
git add -A
git commit -m "사이트 공개"
git branch -M main
git remote add origin https://github.com/chogeonhwi/filmitda-study.git
git push -u origin main
```

# 주의사항

- **파일명은 반드시 영문**으로. macOS는 한글 파일명을 NFD로 저장하는데
  GitHub Pages(리눅스)는 NFC로 요청해서 한글 파일명은 404가 납니다.
  (2026-08-30 이 문제로 12개 파일 전부 영문화했습니다)
- 사이트는 `noindex` + `robots.txt` 로 검색엔진에 노출되지 않습니다.
  링크를 아는 사람만 접근하는 교내 자료용입니다.
- 외부 영화 스틸·시나리오 PDF는 교육 목적 인용입니다. **외부 배포 금지.**

# 2026-09-13 개편 내용

**용량** — HTML에 base64로 박혀 있던 이미지 24장을 `img/` 로 분리.
`index.html` 3.0MB → **1.0MB** (전송 시 gzip 281KB). 이미지는 해당 강의를 열 때만 내려받습니다.

**읽는 느낌** — "AI가 찍어낸 것 같다"는 인상의 원인을 정리했습니다.

| 항목 | 전 | 후 |
|---|---:|---:|
| 콜아웃 박스 | 622개 | 125개 |
| 그중 `TIP` 딱지 | 525개 | 0개 |
| 이모지로 시작하는 제목 | 1,002개 | 0개 |
| 이모지 번호 (1️⃣) | 146개 | 0개 |

- `TIP` 525개 중 **453개는 그냥 설명문**이라 박스를 풀어 본문으로 되돌렸습니다.
  (샷 사이즈 6종을 연속으로 TIP 박스에 넣는 식이 가장 큰 원인이었습니다)
- 나머지는 성격대로 재분류 — 예시 21 · 입시 7 · 인용 38 · 다음강의 6
- 촬영 서적 인용 9곳(`Five C's of Cinematography`, `Painting with Light` 등)은 별도 인용 서식으로
- 이모지 번호 → 앰버색 섹션 번호 (`01`, `02` …)
- "핵심 한 줄 요약" 제목 15개 → 제목 없이 리드 문장으로

**학생 편의** — 전체 검색 추가, 모바일 레이아웃 재조정, 표는 넘칠 때만 스크롤 표시,
폰트 로딩이 본문 표시를 막지 않도록 변경.

**버그 수정** — 기존 `onerror` 84개가 실행될 때마다 오류를 던지고 있었습니다
(`this.parentElement.innerHTML` 로 자기 자신을 지운 뒤 다시 `this.parentElement` 를 참조).
전역 핸들러로 교체 — 이제 이미지가 안 열리면 빈칸 대신 그림 설명 문구가 뜹니다.
`<img>` 태그 155개의 속성 순서 오류도 정리했습니다.
